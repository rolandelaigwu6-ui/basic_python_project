# Wget

- **Project number** 02.03
- **Use** Python 3.11+

## What you are building

- Download a file over HTTP or HTTPS and allow the user to choose where to save it.
- Check the response status before saving. Read the response in pieces and report download progress.

## Example your project must pass

- Download a file from a local test server and check that the saved bytes match the original.

Use any interface the project allows. If an exact route or interface is required above, use it. Write down the exact command or how to call your API, including what inputs it accepts and what it returns.

## Walk through a real example

1. Serve a small file from a local HTTP test server. Download it to a new path and compare the saved file with the original byte for byte.
2. Request a filename that does not exist. Check that the tool reports HTTP 404 and preserves any existing file at the output path.
3. For an interrupted response, check that the tool does not report a complete download.

## Situations you must test

- A server returns 404 for a missing file.
- A download stops before it finishes.
- The server does not report the total length.

For each situation, decide whether it is valid and write down the result you expect. If the operation fails, explain the problem and keep valid files or saved data intact. A command-line program must exit with a nonzero status on failure. A web app must return an HTTP status that matches the problem.

## Engineering work you must also finish

Add timeouts and retries. Use the HTTP Range header for resuming a partial download and verify the server response before adding bytes to it.

Where practical, keep the main logic in functions you can call and test separately from file access, terminal input, or web requests. Write a short design note explaining why you chose your approach, what it makes easier, and where it has drawbacks.
